3. Desarrollo
   3.1 Arquitectura del sistema
       - Diagrama general: OSRM (Docker) ↔ Simulador Python ↔ Resultados
       - docker-compose.yml y despliegue contenerizado
       - Flujo de datos: OSM → .osrm (preprocesamiento CH) → API REST

   3.2 Generación de instancias sintéticas
       - make_synth_orders.py: proceso Poisson no-homogéneo
       - Calibración con LaDe (picos 09:00, 17:00)
       - Distribución geoespacial: polígono urbano La Paz
       - Tiempo de preparación: N(12,3) min
       - Dimensionamiento automático de flota (synth_loader.py)

   3.3 Motor de simulación
       - Ciclo de simulación por épocas (f = 5 min)
       - Máquina de estados de órdenes y couriers
       - Integración con OSRM (getrouteOSMR.py, caché)

   3.4 Política FCFS (baseline)
       - Lógica de asignación reactiva: nearest available courier
       - Activación vía FCFS_POLICY=1

   3.5 Política Rolling Horizon
       3.5.1 Clasificación de órdenes (Grupos I, II, III)
       3.5.2 Bundling por restaurante (bundling.py)
       3.5.3 Matching courier-bundle: Algoritmo Húngaro (asignaciontentativa.py)
       3.5.4 Compromiso en dos etapas y lookahead (Δ₁, Δ₂)

   3.6 Diseño experimental
       - run_experiments.py: 5 escenarios de saturación (18:1 → 75:1)
       - Variación paramétrica (--bundle-sizes, --seeds)
       - Pipeline: generación → FCFS → RH → KPIs

   3.7 Métricas de evaluación (generate_results.py)
       - 21 KPIs: CTD, RTP, RTD, utilización, costo/orden, SLA
       - Modelo de compensación: max(p₁·orders, p₂·hours)
